# ADR-0055: Multi-repo coordination — dispatch and janitor keyed by repository

## Context

ADR-0017 bound coordination to the single `THEOZOLITH_REPO` the `serve` process was started with, while ADR-0044/0047 already let several Stacks of one Worker-Type Definition each bind a different workspace. The two halves disagreed: a second Implementer Stack bound to another repo loaded cleanly, was granted issues from `THEOZOLITH_REPO`, and worked a foreign issue number in its own checkout — a wrong-repo grant enforced only by convention. Grilling 2026-09-02 (issue #96) settled the amendment: the Claim Protocol is keyed by the repository the Driver will actually check out, end to end.

## Decision

- **Bound Workspace** (glossary term): a repository the Control Node coordinates — the workspace of a resolved driver-bearing (process-kind) Stack in the Pinned Build, **regardless of desired state** (a stopped Implementer's zombie claims still need the janitor). Flight Deck workspaces are never bound (decks are not pipeline actors), and a worker Stack's dispatch-verification failure never gates a deck's operation — decks never call dispatch, a structural property, not a carve-out. The bound set scopes dispatch verification, the janitor's sweeps, and the state document's `repos`.
- **Wire**: the dispatch request body gains `repo` (owner/name) and `stack` (the Driver's `THEOZOLITH_STACK`); a request missing either is refused 400. The Control Node verifies the pair against the Pinned Build — the named Stack must exist, be placed on the authenticated node, and resolve to exactly that workspace — otherwise **403** with a detail naming the Stack and both repos. A missing Stack is a 403, not a soft no-grant: a `reason` response is reserved for *verified* requests with nothing eligible, so a typo'd Stack name can never fall back to the request's repo. Verification is fail-open only while the Pinned Build is unreadable or absent (the ADR-0004 deletion-test boot — the existing posture of the pin gates); this is the dev shape's door, alongside declaring a real Stack and setting `THEOZOLITH_STACK`. Reviewer discovery verifies identically.
- **Events**: `theozolith.run` and `theozolith.review` events carry `repo`, required fail-closed (400 without it). `theozolith.run.progress` (keyed by `run_id`) and `theozolith.error` (node/component-scoped) are unchanged. No wire backward compatibility (deployment doctrine); the pin-eligibility gate bounds the skew window to a box mid-update.
- **Settings**: `THEOZOLITH_REPO` is retired from the Control Node; a set variable is a `ConfigError` everywhere control settings load — never silently ignored (the shipped unit never sets it; a lingering hand-configured export must not change coordination behavior without a signal). `coordination_jobs_enabled` becomes "a control PAT is present"; without a PAT, dispatch stays 503. The `serve` startup notice lists the bound repos (or that none are bound), and the sweep loop reads the bound set per pass, so a re-ingest binds or unbinds repos without a restart.
- **Store**: `repo TEXT NOT NULL` joins `grants`, `malformed_states`, `dispatch_waits`, `zombie_flags`, `janitor_actions`, and `chained_dependents`; primary keys become `(repo, issue)` (or `(repo, dependent_pr)`); `drivers` gains `repo` and `stack`. These are cache tables (ADR-0016): the schema bump drops and recreates them, and the next dispatch pass rebuilds them from GitHub. The `events` table is **kept** — `repo` is ALTER-added as an extracted column, and `live_claims()` / `run_states()` exclude repo-less legacy rows from claim logic (a marked legacy fence) while keeping them as metrics history. Accepted gap: a Run in flight across the control upgrade loses zombie coverage — rare, and visible on GitHub either way.
- **Clients**: one `GitHubClient` factory memoized per repo over the one control PAT and one `api_url`. **v1 doctrine: one GitHub host and one control PAT per Control Node** — every bound workspace must be reachable by both (mixing github.com and a GHES instance on one Control Node is out). The single global dispatch lock stays.
- **Per-repo dispatch pause**: `grant_work` / `review_targets` catch `GitHubError` and answer `{"issue": None, "reason": ...}` instead of propagating a 500 — one broken repo must not make a healthy Control Node look broken. The pause is recorded in a per-repo pause cache table in the `malformed_states`/`dispatch_waits` mold — written on a failing pass, cleared on the repo's next successful pass, surfaced in `/api/v1/state`, `theozolith status`, and the TUI. ADR-0053's fail-loud dependency-read posture keeps its identity (the distinct reason text) but rides the same reason path.
- **Janitor**: every pass iterates the bound set, one client per repo, a failing repo isolated from the others exactly as one broken claim is isolated today; `janitor --once` sweeps every bound repo and fails loud on an unreadable config (a human command owes a loud answer). **Unbinding a repo withdraws coordination coverage**: the janitor logs live claims whose repo is not bound and never writes GitHub for them — leftover claims are the operator's. Best-effort coverage from cached live claims was rejected: the cache is deletable (ADR-0016), so it can never back a coverage guarantee.
- **Driver**: `DispatchClient` sends `repo` and `stack` on both roles. The Reviewer's discovery is per repo — one Reviewer Stack per workspace, matching the Implementer.
- **Surfaces**: `/api/v1/state` publishes `repos` (the singular `repo` field is dropped — no compatibility window); every run/grant/wait/malformed/pause row carries its repo, and the dashboard Runs view, TUI, `theozolith status`, and `theozolith flags` render `owner/name#N` with per-row links.
- **Unchanged by this ADR**: cross-repo Dependency Edges stay malformed (ADR-0053) even between two bound workspaces — the Driver's PAT and the Context Tree remain bound to one repo, so the original rejection holds. Node health and quarantine stay node-scoped and repo-agnostic: a node failing consecutively in one repo is quarantined for all (node health is about the node).

## Consequences

- **Positive**: a wrong-repo grant becomes structurally unrepresentable — the request names its repo and the Pinned Build vouches for the pair; identical issue numbers in two workspaces can never collide in the coordination caches; one repo's GitHub trouble pauses that repo visibly instead of 500-ing the fleet's dispatch.
- **Negative**: the wire and the store schema break with no compatibility window — Driver and Control move together (accepted deployment doctrine); the one control PAT must cover every bound workspace (a broader token than any single-repo deployment needed); a repo removed from the config loses janitorial coverage with only a log line to show for it.
- **Neutral**: amends ADR-0017 (the coordination target is every Bound Workspace, named per request; `THEOZOLITH_REPO` retired from the Control Node), ADR-0015 (dispatch API body and state document), and ADR-0016 (janitor scope per bound repo); the ADR-0053 eligibility lanes are untouched; the control PAT's persisted-config gap (env-only today) remains a separate issue.

## Alternatives Considered

- **Missing-Stack fallback to the request's repo**: rejected — reopens the exact convention-not-structure footgun through a typo'd Stack name; fail-open is reserved for an unreadable or absent Pinned Build.
- **Per-repo control PATs**: deferred, not rejected — v1 takes one PAT; a workspace it cannot reach degrades to the per-repo pause, which is the honest surface for the gap.
- **Honoring cross-repo edges between bound workspaces**: rejected again — ADR-0053's grounds (Driver PAT and Context Tree bound to one repo) are untouched by control coordinating several repos.
- **Best-effort janitor sweeps of unbound repos from cached live claims**: rejected — pretends a guarantee the cache-not-archive doctrine cannot back; honest withdrawal plus a log line instead.
- **Dropping the `events` table on the schema bump**: rejected — loses the metrics substrate while buying nothing; the legacy fence has the same (accepted) zombie-coverage gap.
- **Keeping HTTP 500 as the per-repo pause**: rejected — a noisy per-poll failure that makes a healthy Control Node look broken and gives operators no persistent "still paused" surface.
- **Silently ignoring a lingering `THEOZOLITH_REPO`**: rejected — an upgrade must never change coordination behavior without a signal; the fix is one `unset`.
